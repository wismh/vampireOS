# Vampire OS

MBR loads stage 2, which prints `boot` on COM1 (`0x3F8`) in real mode, loads a freestanding C kernel, asks BIOS for the E820 memory map and a VBE linear framebuffer (640×480×32 when the BIOS offers it), enters long mode, maps the kernel into the higher half, and jumps to `kmain`. The kernel prints that map, builds a physical frame allocator from usable RAM, maps that RAM with 2 MiB pages and 4 KiB tails, exposes it through a higher-half direct map, then drops the low identity map. VGA, the framebuffer MMIO, the PMM bitmap and page tables go through that map; the kernel paints a bitmap-font `Vampire OS` banner on the LFB (when VBE is live the kernel also blits `$` or `kbd>` plus the current line buffer onto a bottom row of that LFB so typed input is on the scanout; 80×25 text VGA remains if the mode set fails so `$` still types; `vga_putc` and console `write` fd 1/2 are also mirrored to COM1 at `0x3F8` so QEMU `-serial stdio` shows `$` and accepts keys). The GDT lives in kernel BSS with user-mode selectors and a TSS, the kernel runs on an HHDM stack, runs a small kernel heap, installs a 64-bit IDT, remaps the PIC so IRQs start at vector 32, runs the PIT tick counter, `iretq`s into ring-3 tasks at `0x400000` (each with a private CR3 so A/B/C/echo share that vaddr), copies user `write` strings by walking that task’s page tables through `int 0x30` (a kernel pointer from ring 3 fails), lets those tasks `yield`, `sleep` or `wait` (`wait` with `rdi` 0 reaps any child and with `rdi` set reaps that child; the 8-bit `exit` code returns in `rax`, or -1; the waiter’s row shows it once as `st N`), gives each task its own kernel stack and `TSS.RSP0`, preempts ready tasks on IRQ0, returns to a kernel idle loop on `exit` of the last task, serves `hello` / `motd` / `echo` / `a` / `b` / `c` / `opentest` / `readtest` / `cat` / `ls` / `exectest` / `status` / `waiter` / `pipetest` / `brktest` / `forktest` / `dup2test` / `waitpid` / `fdtest` / `pipefork` / `cowtest` / `stat` / `sleeper` / `catch` / `kill` / `crt` / `hi` / `malloctest` / `sh` / `mmaptest` / `mmapfile` / `munmaptest` / `mprottest` / `fbinfo` / `fbtest` / `fbhello` / `fbclear` / `uptime` from a FAT12 volume in an MBR type 0x01 partition (start LBA 273, after the kernel), read and written by ATA PIO from directory entries and clusters, and runs `help` / `ls` / `mem` / `cat` / `run` / `put` / `rm` / `ps` / `kill` / `uptime` from a PS/2 line buffer (COM1 RX injects into that same buffer;a line with `|` runs the left ELF with fd 1 on the pipe write end and the right ELF with fd 0 on the read end; `cat hello | cat` prints `blood`; a line with one `<`, `>`, or `>>` binds that file onto fd 0 or fd 1 of the ELF so `hi > out` then `cat out` prints `hi 42` and `hi >> out` twice then `cat out` prints `hi 42hi 42`; `ps` lists live slot ids, optional names, RUN/SLEEP/WAIT, and a per-task PIT tick count so `run forktest` shows the extra child; `kill <id>` sets a pending SIGTERM bit so that slot exits on return to user and `ps` drops it; Ctrl+C posts SIGINT on the last `run` ELF (default still terminates; a `sigaction` handler runs instead) and leaves the line buffer). Boot tasks A/B/C load as ELFs from that volume the same way `run` does. Each ELF maps at `0x400000` plus a stack page in that task’s cloned PML4. Up to sixteen tasks; exit tears down user PTEs and page-table pages (cloned PML4 kept until slot reuse); kernel stack freed on DEAD reuse so `run` loops do not drain free frames. Each task runs under its own cloned PML4 (`CR3` switches on schedule; idle and syscalls use the boot map). `run <name>` loads any ring-3 ELF from that volume into a free slot at the shared link address. Ring-3 `open` / `close` / `read` / `lseek` keep an eight-slot per-task fd table (`run` / `fork` / `exec` start with fd 0 keyboard, fd 1 VGA, fd 2 VGA err, all mirrored to COM1; `<` `>` `>>` and `|` still replace those slots); file fds store an offset that `read` starts at and advances; `open` with rsi 2 creates if needed and seeks to the end so a write appends. `stat` fills a user `{size, first cluster, is-dir}` packed-int struct. `kill` sets a pending SIGTERM bit with an 8-bit status (`rdi` pid, `rsi` status) and the target exits on return to user unless a SIGTERM handler is installed. `sigaction` (syscall 27, `rdi` signo, `rsi` handler VA or 0) installs a one-shot handler for SIGINT (2) or SIGTERM (15); `run catch` installs SIGINT, and Ctrl+C prints `caught` once on VGA and the LFB. `write` still takes a user string for VGA, or a small fd with buffer/length for file/`fs_write` (`run readtest` seeks into `hello` and prints `ood`; `run stat hello` prints `5`; `run sleeper` then `kill` that pid or Ctrl+C so `ps` no longer lists it; `run catch` then Ctrl+C prints `caught` once; `run crt` prints `crt` through C-callable `write` / `exit` stubs; `run hi` prints `hi 42` from freestanding C via `printf` (`%s` `%d` `%x` through `write`); `run malloctest` allocates two `brk` heap blocks with `malloc`, frees one, and prints `ok`; after kernel init the image `run`s `init`, which `fork`/`exec`s `sh` so the first prompt is `$` and typing `hi` (no `run sh`) prints `hi 42`; `$` `hi > out` then `cat out` prints `hi 42`; `$` `hi >> out` twice then `cat out` prints `hi 42hi 42`; `$` `hi > out` still overwrites to one `hi 42`; `cat < hello` opens `hello` on fd 0 so user `cat` prints `blood`; `$` `cat hello | cat | cat` is three user `cat`s chained with `pipe`/`fork`/`dup2`/`exec` and prints `blood` without the kernel `|`; `$` `sleeper &` returns `$` at once so `ls` / `help` still type while `ps` lists that sleeper in SLEEP (repeat `&` until slots past 8 show in `ps`); `$` `cd sub` then `ls` lists that directory and `$` `pwd` prints `/sub` (kernel `cd` / `pwd` stay on `kbd>`); `run echo hi` writes `hi` through fd 1; `run cat nosuch` writes `X` through fd 2 onto VGA; `exit` or `kill` of that shell pid makes `init` start `sh` again and `ps` still lists `init`; `run sh` then `hi` still `exec`s that ELF from the user shell; kernel `help` / `ls` remain as fallback; `run cat hello` runs the user `cat` ELF with argv on the user stack; `run ls` lists the cwd from ring 3 via `readdir`; `run exectest` `exec`s into `echo` in the same task slot; `run status` exits 42; `run waitpid` forks two children that exit 1 and 2 and prints both codes; `run fdtest` opens `hello` five times so the fifth fd is 7 (0/1/2 are console); `pipe` fills two user ints from `rdi` (read end, write end) backed by a one-page kernel ring, `run pipetest` writes a short string through that ring then prints it; `cat hello | cat` does the same across two tasks; `brk` grows the user heap past the stack page and `run brktest` stores a byte above `0x401000` then prints it; `mmap` maps N anonymous user pages at a chosen address (length rounded up to 4 KiB, not the heap) and `run mmaptest` maps three pages at `0x500000`, stores `mmap` on the last (`0x502000`), and writes it; with `rdx` a file fd it copies that file into the mapping so `run mmapfile` opens `hello` and writes `blood` from the mapping without `read`; `munmap` (syscall 23) drops that range so `run munmaptest` unmaps `0x500000`, writes `ok`, a `write` of that VA returns `-1`, `mem` shows the frame back, and a store after a short sleep `#PF`-kills the task; `mprotect` (syscall 28) changes user page prot (RO/RW) so `run mprottest` maps at `0x500000`, marks it RO, writes `ro`, and a store `#PF`-kills the task while `run cowtest` still prints different parent/child values; `fbinfo` (syscall 24) fills a user `{width, height, pitch, phys}` packed-int struct so `run fbinfo` prints `640x480` (or whatever linear mode actually booted); `fbpix` (syscall 25) fills a user `{x, y, w, h, color}` packed-int rectangle on a PMM shadow of the LFB so `run fbtest` paints a bar and a text overlay row still shows `$`; `fbpresent` (syscall 26) copies that shadow onto the scanout in one blit; `run fbhello` draws `hello` with a userland 8×8 bitmap font through `SYS_FBPIX` then `SYS_FBPRESENT`, not the kernel banner path; `run fbclear` fills the shadow with a solid color, the kernel puts `$` back on the overlay row, and `SYS_FBPRESENT` copies fill plus `$` in one present so the next prompt is still visible; typing at `$` redraws `$` plus the line buffer on the shadow and presents so a screenshot shows `$ls` on the framebuffer; a left click on the PS/2 mouse prints `x,y` once on VGA and on that scanout; boot PCI-scans for virtio-blk (vendor `0x1AF4`, device `0x1001` or virtio 1.0 `0x1042`), virtqueue-reads LBA 0, and prints `virt 55aa` (MBR magic) on VGA and the LFB; it also PCI-scans for an AHCI controller (class `0x0106`), DMA-reads LBA 0, and prints `ahci 55aa`; FAT `bread`/`bwrite` go through a block table (VirtIO when virtio-blk probed — first write prints `virt wr` — else AHCI DMA — first write prints `ahci wr` — else ATA PIO); `$` `devs` lists probed backends (`virt ahci ata`); `uptime` returns PIT seconds (`idt_ticks() / 100`) and kernel `uptime` or `$` `uptime` prints that integer; `fork` shares the current task’s user pages as read-only until a write and `run forktest` prints from both parent and child; `run cowtest` `brk`s a heap page then parent and child store different bytes there so each prints a different value; `run pipefork` has the child write a string through a pipe and the parent print it on VGA without the kernel `|`; `dup2` remaps an fd onto another slot and `run dup2test` writes through the remapped fd onto VGA; `wait` reaps a chosen child after `fork` records the parent slot; each task keeps its own cwd, `fork` inherits it, and `run` snapshots the kernel shell cwd so `cd a` then `run ls` lists `a` while `cd b` then `run ls` lists `b`; `chdir` (syscall 20) changes the calling task’s cwd and `getcwd` (21) copies `/` or `/sub` so user `sh` builtins `cd` / `pwd` work). `put hello fang` overwrites `hello` on disk. `put note dusk` allocates a free cluster and a new directory entry. `rm note` marks that directory entry deleted and frees the cluster chain only when no other dirent in that directory shares the same first cluster (FAT12 has no inode; that scan is nlink). `$` `ln hello dual` adds a second 8.3 dirent on hello’s cluster so `cat dual` prints `blood` after `rm hello`; a last `rm dual` frees the chain (`cat dual` prints `?`); `ln` of a directory prints `?`. `mv note dusk` renames that entry in the same parent; `mv sub/note dusk` rewrites both parents and leaves the file clusters put (an existing dest name prints `?`). `cp hello dusk` copies `hello` onto a new directory entry and new clusters so `cat dusk` prints `blood`. `$` `cp hello sub/hello` copies into an existing directory so `cat sub/hello` prints `blood` and `ls sub` lists `hello`. `fill note 600` writes a 600-byte FAT chain. `trunc note 5` after that sets the dirent size to five bytes and frees the trailing cluster so `cat note` prints five `x`s. `mkdir sub` / `cd sub` / `cd ..` walk a subdirectory. `pwd` prints `/` or `/sub`. `rmdir sub` removes an empty directory. A subdirectory that fills its first cluster grows onto the next FAT cluster. The volume root does the same after its 16 reserved slots fill. The FAT12 data region has 1024 clusters and each FAT is four sectors, so `fill` can occupy a cluster whose FAT12 entry sits past the first two FAT sectors. `fill note 2048` still lists and `cat`s. `$` `sync` rewrites both FAT copies and the cwd directory, then flushes the active block device (VirtIO `BLK_T_FLUSH`, else AHCI FLUSH CACHE `E7h` via DMA, else ATA `E7h`) so a file created then synced is still there after a cold QEMU restart. `cat sub/note` and `put sub/note dusk` use that path without changing the cwd. `ls` lists `longname.txt` from a packed VFAT long-name entry (8.3 alias `LONGNA~1.TXT`); `cat longname.txt` prints `long`. `hi > longername.txt` (or `put` / `cp hello longername.txt`) writes LFN entries plus an 8.3 alias so `ls` lists `longername.txt` and `cat longername.txt` prints `hi 42`.

## Dependencies

- [NASM](https://www.nasm.us/)
- [CMake](https://cmake.org/) 3.20+
- [LLVM](https://llvm.org/) (`clang`, `ld.lld`, `llvm-objcopy`)
- [QEMU](https://www.qemu.org/) (`qemu-system-x86_64`)

On Windows (pick one):

```text
winget install NASM.NASM SoftwareFreedomConservancy.QEMU LLVM.LLVM
choco install nasm qemu llvm
scoop install nasm qemu llvm
```

NASM, LLVM, and QEMU must be on `PATH` (or under `C:\Program Files\NASM`, `C:\Program Files\LLVM\bin`, `C:\Program Files\qemu`).

## Build

```text
cmake -B build
cmake --build build
```

This produces `build/vampire.img`.

## Run

```text
cmake --build build --target run
```

QEMU uses `-vga std` so stage 2 can set a VBE linear mode, and `-serial stdio` so COM1 (stage 2 `boot`, then `$` and console writes) shows on the terminal. BIOS boots the IDE disk (`if=ide,cache=writethrough`). The same image is also attached to AHCI and to virtio-blk with no snapshot (`file.locking=off`, `cache=writethrough`):

```text
-drive format=raw,file=build/vampire.img,if=ide,cache=writethrough,file.locking=off
-device ahci,id=ahci
-drive id=ahci-hd,file=build/vampire.img,if=none,format=raw,cache=writethrough,file.locking=off
-device ide-hd,drive=ahci-hd,bus=ahci.0
-drive id=virtio-hd,file=build/vampire.img,if=none,format=raw,cache=writethrough,file.locking=off
-device virtio-blk-pci,drive=virtio-hd
-serial stdio
```

`file.locking=off` lets the IDE, AHCI, and VirtIO views open the file. Do not use `snapshot=on` on the AHCI or VirtIO drives — those writes must reach the file. The backends are the same host file, not independent copies. Boot should print `virt 55aa` and `ahci 55aa`. `$` `devs` lists probed backends (`virt ahci ata`). After `$ hi > virt.txt` then `$ sync`, a cold restart still `cat`s `virt.txt`. `$` `sync` issues VirtIO `BLK_T_FLUSH` when virtio-blk is the FS device (VGA prints `virt flush` once), else AHCI `E7h` (`ahci flush`), else ATA `E7h`. FAT uses `bread`/`bwrite` (VirtIO when present, else AHCI, else ATA) plus the MBR partition start (type `0x01`, LBA 273). Boot prints `part 273`. `$` `ls` and `cat hello` (`blood`) work with that non-zero FAT start. `$` `cat bad` reads a packed dirent whose first cluster is `0x0F00` (past the disk); `bread` returns `-1` instead of hanging, `cat` prints `?`, and `$` returns.
